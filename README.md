# Notebook Arena — ігровий прототип

Відкрий `project.godot` у Godot 4.7 і натисни **F5** для запуску. У меню доступні бій проти ботів і гра до чотирьох гравців через WLAN. У настройках можна задати ім'я гравця, гучність і повноекранний режим. `Esc` відкриває паузу.

Ім'я з'являється над персонажем, а стрічка вбивств призначена для боїв між гравцями; роботи й дрон у неї не потрапляють. Меню та ігрові написи використовують передані аркуші літер у `assets/user_font_latin.png` і `assets/user_font_cyrillic.png`. Фон меню — `assets/menu_backdrop.png`.

Арена побудована з одного намальованого зображення островів і окремої чорно-білої маски колізії. Спавни, предмети та бойові позиції задані вручну в `scripts/level_design.gd`.

## Керування

- `A/D` або стрілки — рух по арені; `Space` / `W` — стрибок, утримання в повітрі вмикає jetpack;
- миша — приціл, ЛКМ — стріляти, ПКМ — зарезервована secondary action;
- `Q` — удар зблизька (`skill_1`), `R` — перезарядити (`skill_2`), `T` — наступна зброя (`skill_3`), `F` або `G` — граната (`skill_4`);
- `E` — підібрати предмет поруч; `1`–`8` — вибрати зброю; колесо миші / `+` / `-` — зум, `0` — стандартний масштаб;
- `Esc` — пауза / скасування; кнопки дій у HUD і геймпад активують ті самі actions;
- `F2` — debug-панель вводу, `F3` — debug-карта маршрутів, спавнів, предметів, стрибків, дальності зброї та зон руйнування.

На touchscreen з'являються аналоговий джойстик зліва, кнопки гранати / jetpack / удару справа та пауза у верхній частині екрана. Лівий джойстик рухає персонажа; якщо відхилити його вгору, персонаж стрибає і в повітрі вмикає jetpack. Великий кулак справа працює як приціл і стрільба: затисни та перетягни його в напрямку пострілу; короткий тап завдає удару зблизька. Дотик у вільній правій частині також прицілює й стріляє. Кнопка підбору з'являється лише поруч із предметом. Керування підтримує одночасні дотики й safe area пристрою; окрема кнопка jetpack теж працює. У цій грі `skill_1–4` збережені на доступних діях — кулак, перезарядка, перемикання зброї та граната; окремої системи чотирьох бойових навичок у грі поки немає. `secondary_action` також зарезервована й зараз не має ігрового ефекту.

Геймпад: лівий стік — рух, правий — приціл, A/Cross — стрибок, X/Square — стрільба, B/Circle — скасувати, Y/Triangle — взаємодія, LB/L1 — перезарядка, RB/R1 — наступна зброя, натискання лівого стіка — удар, правого — граната, Start — пауза. Назви кнопок залежать від контролера й драйвера; рушій зіставляє стандартні індекси XInput/SDL.

### WLAN гра

Усі пристрої мають бути підключені до однієї Wi‑Fi мережі.

1. На одному ПК або Android-пристрої відкрий гру, вибери **CO-OP WLAN → СТВОРИТИ ХОСТ**.
2. На іншому ПК або Android відкрий **CO-OP WLAN → ЗНАЙТИ КІМНАТИ** й натисни знайдену кімнату. Обидва пристрої мають бути в одній Wi‑Fi мережі.
3. Для браузера відкрий адресу Web-гри, яку показує хост, і натисни **ПРИЄДНАТИСЯ ДО ЦЬОГО ХОСТА**. Якщо пошук кімнати не спрацював, запасний пункт **ВВЕСТИ АДРЕСУ ВРУЧНУ** дозволяє ввести `IP:8910`.

Хост доступний у версіях `.exe` та `.apk`; Web-версія підключається до них як клієнт. Якщо Windows попросить доступ до мережі, дозволь його для приватних мереж. Порти `8910` (WebSocket), `8911` (пошук кімнат через UDP) і `8088` (Web-гра) мають бути доступні в локальній мережі. Браузери не підтримують UDP-пошук, тому для Web потрібне посилання хоста або ручне введення адреси. Деякі роутери вимикають зв'язок між пристроями Wi‑Fi: у такому разі ввімкни локальний обмін у налаштуваннях мережі або скористайся ручною адресою. Матч між гравцями не створює ботів і дронів.

### Окремі збірки EXE та APK

У `export_presets.cfg` є пресети **Windows Desktop** і **Android APK**. Результати лежать у `build/NotebookArena.exe` та `build/NotebookArena.apk`.

```powershell
godot --headless --path . --export-release "Windows Desktop" build/NotebookArena.exe
godot --headless --path . --export-debug "Android APK" build/NotebookArena.apk
```

Перед першим експортом встанови шаблони експорту саме для версії Godot у проєкті. Для Android також потрібні JDK 17 і Android SDK (`platform-tools`, `build-tools;35.0.1`, `platforms;android-35`). APK з debug-експортом призначений для встановлення й перевірки; публікація в магазині потребуватиме власного ключа підпису.

### Web export

`export_presets.cfg` містить preset `Web`, який використовує `web/index.html`. HTML обмежує браузерні жести лише ігровим canvas, задає `viewport-fit=cover`, вимикає виділення та викликає стандартний Godot Web runner. Зібрати гру можна так:

```powershell
godot --headless --path . --export-release Web build/web/index.html
```

Для Android/iOS native builds Godot отримує safe area через `DisplayServer`; для Web preset використовується той самий API. CSS/render масштабування веде Godot, а HUD перебудовується після зміни розміру й орієнтації.

### Публічна Web-версія

GitHub Actions публікує `build/web` на GitHub Pages: <https://zhuravskayyar.github.io/stikman/>. Після змін гри експортуй Web preset і додай оновлені файли з `build/web` до коміту — пуш у `main` запустить новий деплой. Сайт відкривається через HTTPS, тож WebAudio працює і з телефона.

Лінія від дула показує траєкторію до першої перешкоди. Чотири роботи та один дрон прилітають зверху, оминають породу променевими пробами й продовжують шукати гравця, навіть якщо пряма лінія атаки перекрита; людських ботів більше немає. Дрон має невелику зону агру, патрулює свою ділянку й атакує тільки після входу гравця в радіус. Після знищення він повертається лише через 10 секунд, тому арена не заповнюється дронами. Роботи використовують різну зброю і гублять її після поразки. Гранатомет вибухає при влучанні. Пила-диск летить до чотирьох секунд і, влучивши у ворога, тримається на ньому та завдає періодичної шкоди до кінця польоту. Сюрикен одразу ранить ціль або встряє в породу пасткою на п'ять секунд; наступивши на неї, можна отримати шкоду. Нові види зброї також лежать на спірних маршрутах. Після смерті гравець відроджується лише з пістолетом. Дробовик стріляє шістьма дробинами, снайперка завдає більшої шкоди, а ракета вибухає й б’є по області.

Terrain зберігається в `assets/arena_visual.png`, а біла частина маски `assets/arena_mask.png` означає тверду землю. Вибух вирізає однакову круглу область з обох зображень і оновлює лише зачеплені рядки колізії. Якщо впасти у воду під островами, гравець гине. Аптечки й набої лежать на спірних маршрутах, а сильна зброя приходить із ворогами.

## Структура

Спрайти лежать окремими атласами в `assets/`. Прямокутники кадрів і посилання на іконки зібрані в `scripts/art.gd`; подвійні пістолети й Uzi мають окремі прозорі спрайти. Дрон і робот анімуються з `assets/drone_atlas.png` та `assets/robot_atlas.png`. Інтерфейс використовує `assets/hud_sketch.png`: його контури HP, каністри та кнопок. Поточна зброя показана поруч її оригінальним спрайтом, без текстових підписів. Зброя й руки додаються окремо через `WeaponPivot` у `scripts/player.gd`.

SFX відтворює автозавантажений `scripts/audio_manager.gd`: він вибирає випадкову варіацію та трохи змінює висоту тону. OGG лежать у `assets/audio/` за категоріями; авторство й ліцензія паку — в `assets/audio/CREDITS.md`.

Ранець перемикає кадри з атласу; полум’я й іскри анімуються кодом. Terrain читає маску зображення з кроком 4 пікселі й збирає суцільні горизонтальні відрізки в прості колайдери. Після вибуху змінюються альфа-канал арту, маска та лише локальні рядки колізії.

## Перевірка

Перевірка ігрової петлі: `godot --headless --path . --script res://tests/smoke.gd`. Перевірка Input Actions, multitouch, touch HUD, UI consumption і скидання стану: `godot --headless --path . --script res://tests/input_smoke.gd`. У debug build натисни `F2`, щоб побачити пристрій, actions, вектори, активні дотики, viewport, DPR і орієнтацію.

### Оновлення гри

При запуску меню звіряє встановлену версію з останнім GitHub Release. `.exe` завантажується й замінюється після закриття гри, `.apk` завантажується та відкриває системне встановлення, а браузерна гра перезавантажує актуальну сторінку. Android просить підтвердити встановлення; якщо Android не дозволяє встановлення з гри, треба дозволити його в системних налаштуваннях.

Публікація запускається тегом `vMAJOR.MINOR.PATCH`, наприклад `v1.0.2`. GitHub Actions збирає Windows, Android і Web та прикріплює їх до релізу. Наразі GitHub Release ще не створено, тож автоматичне оновлення стане доступним після першої публікації.

Щоб наступні APK могли оновити вже встановлений APK, GitHub Actions має підписувати їх тим самим debug-ключем. Додай у налаштування репозиторію GitHub Actions secret `ANDROID_DEBUG_KEYSTORE_BASE64` із вмістом `C:\Users\yarik\AppData\Roaming\Godot\keystores\debug.keystore`, закодованим у Base64. У PowerShell Base64 можна отримати командою `[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:APPDATA\Godot\keystores\debug.keystore"))`; скопіюй результат напряму в GitHub Secret і не публікуй його в репозиторії.
